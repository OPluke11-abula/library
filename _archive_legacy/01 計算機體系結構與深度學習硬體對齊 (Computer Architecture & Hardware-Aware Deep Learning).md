# 計算機體系結構與深度學習硬體對齊 (Computer Architecture & Hardware-Aware Deep Learning)

## 核心提問
在深度學習模型設計中，為什麼神經元數量（Hidden Units）普遍被設定為 ^n$（例如 256, 128, 64, 32）？這背後到底有什麼計算機體系結構與 GPU 底層硬體的支持？

---

## 一、GPU 微架構與執行緒調度（Warp Scheduling）

現代深度學習依賴 GPU（如 NVIDIA CUDA 架構）進行高並行矩陣運算。在硬體底層，運算資源的組織具有高度階層性：

1. **Warp（執行緒束）**：
   - NVIDIA GPU 的 Streaming Multiprocessor (SM) 執行指令的最小調度單元是 **32 個執行緒**（Thread），稱為一個 Warp。
   - SIMT（Single Instruction, Multiple Threads）：同一個 Warp 內的 32 個執行緒在同一個時鐘週期執行相同的指令。
   - 若神經元數量或矩陣維度不是 32 的倍數（例如設為 20、35、50），最後一個 Warp 就會出現嚴重的「執行緒發散（Thread Divergence）」或「空轉閒置（Idle Threads）」，硬體算力利用率直接下降。

2. **Tensor Cores 與矩陣瓦片計算（Matrix Tiling & GEMM）**：
   - 全連結層本質是通用矩陣乘法： = X \cdot W + b$。
   - Tensor Cores（如 NVIDIA Turing / Ampere 架構）以硬體微瓦片（Hardware Micro-Tiles）為基本計算塊，常見規格為  	imes 16 	imes 16$ 或  	imes 8 	imes 4$。
   - 維度為 ^n$（如 256, 128, 64, 32）時，大矩陣可以被無縫切割成整數倍的硬體瓦片，完全不需填充（Padding）額外的無效零，避免記憶體與計算資源浪費。

---

## 二、記憶體對齊與快取合併（Memory Alignment & Coalescing）

計算機的記憶體架構遵循二進制定址規則：

1. **記憶體邊界對齊（Alignment）**：
   - CPU 與 GPU 存取記憶體時，以快取行（Cache Line, 典型為 64 或 128 位元組）為單位進行傳輸。
   - 若矩陣維度設定為 ^n$，每個張量區塊的起始位址與步幅（Stride）能自然對齊在 64/128-byte 邊界上。
2. **合併記憶體存取（Coalesced Memory Access）**：
   - 當同一個 Warp 的 32 個執行緒同時請求連續的記憶體位址時，GPU 記憶體控制器能將其合併為**單一次記憶體事務（Memory Transaction）**。
   - 若維度未對齊，單次運算將被迫拆分成 2 次甚至更多次記憶體讀取，造成 DRAM 頻寬浪費與延遲暴增。

## 三、金字塔特徵結構的參數量與計算代價平衡

在本次專案中，我們設計的 4 層架構為：
	ext{Input: } 784 	o 256 \, (2^8) 	o 128 \, (2^7) 	o 64 \, (2^6) 	o 32 \, (2^5) 	o 10

### 參數量精確計算：
1. Layer 1:  	imes 256 + 256 = 200,960$
2. Layer 2:  	imes 128 + 128 = 32,896$
3. Layer 3:  	imes 64 + 64 = 8,256$
4. Layer 4:  	imes 32 + 32 = 2,080$
5. Output:  	imes 10 + 10 = 330$
- **總可訓練參數**：,522$（約 24.5 萬）

### 為什麼不採用均勻寬度（如 256 -> 256 -> 256 -> 256）？
- 若每層均設為 256，參數量將飆升至：
  200,960 + (256 	imes 256 + 256) 	imes 3 pprox 398,000
- 全連結層每增加一層，參數與計算量呈平方級暴增。
- 「前寬後窄」的金字塔設計：在靠近像素的底層給予足夠維度（256）捕捉多樣轉折與邊界；後續逐層收斂，強迫網路丟棄雜訊、濃縮高階抽象語意，在**特徵表達容量**與**防止過擬合**之間取得數學與工程的最優平衡。

## 專題基石總結
軟體與演算法不能脫離底層硬體微架構思考。懂得 ^n$ 背後的記憶體對齊與 Warp 排程，是在設計任何高效能分散式系統、邊緣運算晶片加速時必備的核心素養。
